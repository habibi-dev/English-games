# English Grammar Quest

بازی تمرین انگلیسی به صورت PWA. محتوا (کتاب، درس و تمرین) از فایل‌های JSON خوانده می‌شود و بازی خودش سؤال نمی‌سازد.

## ساختار پوشه‌ها

| مسیر | کاربرد |
| --- | --- |
| `content/index.json` | فهرست سری‌ها، کتاب‌ها و درس‌ها. هر درس یک فایل JSON است. |
| `content/<کتاب>/<درس>.json` | تمرین‌های یک درس. |
| `content/covers/` | تصویر سری (لوگو) و جلد کتاب‌ها که در صفحه‌ی انتخاب نمایش داده می‌شوند. |
| `js/` | کد برنامه (بدون مرحله‌ی build). |
| `css/`, `index.html`, `sw.js`, `manifest.webmanifest` | ظاهر و PWA. |
| `tests/` | تست‌های واحد (`npm test`). |

## اجرا

**با داکر (پیشنهادی):**

```
docker compose up -d --build
```

سپس `http://localhost:8080` را باز کن.

**بدون داکر:** پوشه‌ی پروژه را با هر سرور استاتیک اجرا کن، مثلاً:

```
python -m http.server 8080
```

## ساختار محتوا

محتوا چهار سطح دارد: **سری ← کتاب ← درس ← تمرین ← سؤال**. مثلاً سری `Evolve` شامل کتاب `Evolve 1` است.

### فهرست: `content/index.json`

```json
{
  "schema_version": "3.0",
  "series": [
    {
      "id": "evolve",
      "title": "Evolve",
      "logo": "content/covers/evolve-logo.png",
      "books": [
        {
          "id": "evolve-1",
          "title": "Evolve 1",
          "level": "A1",
          "cover": "content/covers/evolve-1.png",
          "lessons": [
            { "id": "lesson-01", "title": "درس ۱", "file": "content/evolve-1/lesson-01.json", "version": "1" }
          ]
        }
      ]
    }
  ]
}
```

- `id` سری، کتاب و درس در کل برنامه یکتا باشد. ترکیب `کتاب/درس` کلید درس است.
- `logo` و `cover` مسیر تصویر نسبت به ریشه‌ی سایت‌اند (اختیاری). تصویر را در `content/covers/` بگذار.
- `level` سطح کتاب است (مثلاً `A1`) و زیر جلد نمایش داده می‌شود (اختیاری).
- `file` مسیر فایل درس نسبت به ریشه‌ی سایت است.
- ترتیب نمایش همان ترتیب فهرست است.
- `version` را وقتی عوض کن که فایل درس تغییر کرده است (بخش «به‌روزرسانی» را ببین).

### فایل درس: `content/evolve-1/lesson-01.json`

```json
{
  "schema_version": "2.0",
  "book": "evolve-1",
  "lesson": "lesson-01",
  "title": "درس ۱",
  "exercises": [
    {
      "id": "l01-negative",
      "type": "positive_negative_question",
      "title": "تبدیل به منفی",
      "presentation": "text",
      "operation": "negative",
      "difficulty": "easy",
      "items": [
        {
          "id": "l01-neg-01",
          "question": "جمله را منفی کن: She is a teacher.",
          "expected_answer": "She is not a teacher.",
          "accepted_answers": ["She isn't a teacher."],
          "explanation": "بعد از is کلمه‌ی not می‌آید.",
          "glossary": [{ "word": "teacher", "meaning": "معلم" }],
          "points": 10,
          "time_limit": 25
        }
      ]
    }
  ]
}
```

**تمرین (`exercises`)** هر کدام این فیلدها را دارد:

| فیلد | معنی |
| --- | --- |
| `id` | شناسه‌ی تمرین (برای راهنمایی، در بازی استفاده نمی‌شود). |
| `type` | نوع تمرین. باید یکی از این‌ها باشد: `quick_translation`، `sentence_builder`، `grammar_correction`، `multiple_choice`، `positive_negative_question`، `voice_translation`، `dictation` (املا)، `vocabulary` (مترادف و متضاد). |
| `presentation` | `text` یعنی جمله‌ی انگلیسی نشان داده شود؛ `audio` یعنی فقط دکمه‌ی پخش. برای `dictation` پیش‌فرض `audio` است. |
| `operation` | فقط برای `positive_negative_question`: `negative`، `positive` یا `question`. |
| `difficulty` | `easy`، `medium` یا `hard`. امتیاز پیش‌فرض هم از همین می‌آید. |
| `topic`، `answer_mode`، `min_items` | اختیاری. هر سؤال از تمرین به این مقدارها ارث می‌برد. |
| `items` | سؤال‌های تمرین (فیلدهای سؤال را در بخش بعد ببین). |

هر فیلدی که در `items` بیاید، مقدار تمرین را برای همان سؤال عوض می‌کند. مثلاً سؤالی در تمرین منفی‌سازی می‌تواند `"operation": "question"` داشته باشد.

**سؤال (`items`)**:

- `id`: در کل برنامه یکتا باشد، مثلاً `l01-neg-01`. شناسه‌ها برای ذخیره‌ی پیشرفت استفاده می‌شوند، پس بعد از ساختن آن‌ها را عوض نکن.
- `question`: متن سؤال. اگر جمله‌ی انگلیسی داشته باشد، بعد از دو نقطه (`:`) نوشته می‌شود و بقیه‌ی متن راهنمای فارسی است.
- `expected_answer`: پاسخ اصلی. خودش به `accepted_answers` اضافه می‌شود.
- `accepted_answers`: پاسخ‌های دیگر که قبول‌اند (آرایه).
- `answer_mode` و `min_items`: برای سؤال‌هایی که چند مورد می‌خواهند (مثلاً «دو مترادف بگو»):
  ```json
  { "answer_mode": "list", "min_items": 2, "expected_answer": "large", "accepted_answers": ["large", "huge", "great"] }
  ```
  کاربر چند مورد را با `،` یا `,` جدا می‌کند و اگر حداقل `min_items` مورد از فهرست درست باشد، درست است.
- برنامه هیچ شکلی را خودش نمی‌سازد؛ پاسخ فقط وقتی درست است که با یکی از `accepted_answers` یکی باشد (فقط فاصله، کاما، حروف بزرگ/کوچک و نقطه‌ی پایانی نادیده گرفته می‌شوند).
  - اگر هر دو شکل مخفف و کامل قبول‌اند، هر دو را در `accepted_answers` بگذار: مثلاً `"She is not a teacher."` و `"She isn't a teacher."`.
  - پاسخ‌های وارونه مثل `Isn't she?` و `Is she not?` هم جدا هستند و هر کدام باید در فهرست بیاید.
- `explanation`: توضیح بعد از پاسخ اشتباه.
- `glossary`: کلمه‌های کلیدی با معنی. روی آن‌ها در بازی ضربه می‌زنی و معنی‌شان را می‌بینی.
- `word_bank` (فقط `sentence_builder`): کلمه‌های جمله، به ترتیب دلخواه. باید همان کلمات `expected_answer` باشند.
- `options` (فقط `multiple_choice`): گزینه‌ها. پاسخ درست باید یکی از آن‌ها باشد.
- `incorrect_sentence` (فقط `grammar_correction`): جمله‌ی اشتباه.
- `points`، `time_limit`، `enabled`، `hint`: اختیاری.

سؤال‌های نامعتبر گزارش می‌شوند و بقیه‌ی درس بارگذاری می‌شود. قواعد کامل را در `js/bank/schema.js` و `js/bank/content.js` ببین.

## افزودن یک درس جدید

۱. فایل JSON درس را در `content/<کتاب>/` بگذار، مثلاً `content/evolve-1/lesson-02.json`.
۲. یک ورودی به `lessons` همان کتاب در `content/index.json` اضافه کن، با `id` و `file` و `version`.
۳. برنامه را دوباره بساز و اجرا کن:

```
docker compose up -d --build
```

۴. صفحه را باز کن. درس جدید خودکار بارگذاری می‌شود. در صفحه‌ی بازی، کتاب را انتخاب کن و درس جدید در فهرست درس‌ها ظاهر می‌شود.

کتاب جدید هم همین‌طور است: یک آیتم جدید در `books` با فهرست درس‌هایش.

## به‌روزرسانی یک درس

تغییر در فایل JSON یک درس به‌تنهایی روی دستگاه‌ها اعمال نمی‌شود. برای اعمال تغییرات:

۱. فایل درس را تغییر بده (سؤال اضافه، حذف یا ویرایش).
۲. در `content/index.json`، مقدار `version` همان درس را عوض کن (مثلاً از `"1"` به `"2"`).
۳. `docker compose up -d --build` را اجرا کن و صفحه را باز کن.

وقتی `version` یا مسیر `file` تغییر کند، برنامه آن درس را دوباره بارگذاری می‌کند:

- سؤال‌های همان درس به‌روز می‌شوند (با همان `id` بازنویسی می‌شوند).
- سؤال‌هایی که از فایل حذف شده‌اند، از دستگاه هم حذف می‌شوند.
- **تغییرات دستی همان سؤال‌ها در بخش مدیریت سؤال‌ها با این کار بازنویسی می‌شوند.** اگر می‌خواهی ویرایش دستی بماند، آن را در فایل JSON هم اعمال کن.

اگر درسی را از `content/index.json` حذف کنی، سؤال‌ها و اطلاعات آن درس از دستگاه پاک می‌شوند.

همه‌ی درس‌ها یک‌جا را هم می‌توانی از بخش مدیریت سؤال‌ها با دکمه‌ی «بازگردانی از فایل‌های درس» دوباره بخوانی.

## نسخه‌ی قبلی داده

نسخه‌ی ۲ ساختار محتوا را عوض کرده و بانک‌های سؤال قبلی (`banks/` و `banks.json`) حذف شده‌اند. روی دستگاهی که بازی قبلاً باز شده، سؤال‌های قدیمی هنگام اجرای نسخه‌ی جدید پاک می‌شوند. پیشرفت و گزارش‌های کاربر (تلاش‌ها) نگه داشته می‌شود.

## خطاهای بارگذاری

- سؤال‌های نامعتبر گزارش می‌شوند و بقیه‌ی سؤال‌ها بارگذاری می‌شوند. جزئیات در کنسول مرورگر (`console`) و در بخش مدیریت سؤال‌ها دیده می‌شود.
- اگر فایل یک درس پیدا نشود، JSON آن خراب باشد یا هیچ سؤال معتبری نداشته باشد، فقط همان درس خطا می‌دهد و بقیه‌ی درس‌ها بارگذاری می‌شوند. سؤال‌های قبلی آن درس دست‌نخورده می‌مانند.

## استقرار

آدرس عمومی برنامه: <https://eng.wortschatz.site/>

ایمیج داکر فقط فایل‌های استاتیک را سرو می‌کند. فایل‌های JSON و JS و CSS همیشه از سرور تازه گرفته می‌شوند (`no-cache`)، پس بعد از هر بار `up --build` نسخه‌ی جدید به کاربران می‌رسد.

### استقرار خودکار (GitHub Actions)

با هر push به شاخه‌ی `master` یا `main`، ورک‌فلو `.github/workflows/ci.yml` اول تست‌ها را اجرا می‌کند و بعد با SSH به سرور وصل می‌شود، همان شاخه را در مسیر دیپلوی می‌گیرد و `scripts/deploy.sh` را اجرا می‌کند. pull request فقط تست می‌شود.

`scripts/deploy.sh` اگر به Docker دسترسی داشته باشد `docker compose up -d --build` را اجرا می‌کند. اگر سوکت داکر برای این کاربر بسته باشد، همان `nginx.conf` را با nginx سیستم، روی پورت ۸۰۸۰، به‌صورت سرویس کاربر systemd اجرا می‌کند.

Secretهای لازم در GitHub Actions: `SSH_HOST`، `SSH_USER`، `SSH_PRIVATE_KEY`، `DEPLOY_PATH`. `SSH_PORT` و `SSH_KNOWN_HOSTS` اختیاری‌اند. رمز عبور را داخل ریپو یا ورک‌فلو نگذار.
